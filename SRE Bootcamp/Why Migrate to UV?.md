Even though our `requirements.txt` already pins exact package versions (e.g., `Flask==3.0.3`), migrating to **uv** provides several advantages for both local development and SRE workflows.

When you use `uv`, you **always run the application inside the virtual environment** when executing commands.

**`uv run` automatically does the following under the hood:**

1. It checks if a virtual environment (`.venv/`) exists at the root of the project. If it doesn't, it creates one.
2. It checks if the dependencies in `pyproject.toml` match the ones installed in `.venv/`. If they don't, it automatically syncs them.
3. **It runs the command (`python run.py`) inside that virtual environment.**

You do **not** need to manually activate the environment with `source .venv/bin/activate` or specify `.venv/bin/python`. `uv run` handles the activation and execution inside the virtual environment for you.

## 1. Faster Package Installation

- Written in **Rust**, making it significantly faster than traditional Python package managers.
- Downloads and installs packages concurrently.
- Reduces:
  - Local setup time
  - CI/CD pipeline execution time
  - Docker build time

**Benefit:** Faster developer onboarding and quicker deployments.

---

## 2. Clear Dependency Separation

With `requirements.txt`, direct dependencies and transitive dependencies are mixed together in a single flat list.

### Example

```text
Flask==3.0.3
Werkzeug==3.1.3
click==8.2.1
Jinja2==3.1.6
...
```

It's difficult to distinguish:

- Packages we intentionally chose.
- Packages installed automatically as dependencies.

### With UV

#### `pyproject.toml`

Contains only the packages we directly depend on.

```toml
dependencies = [
  "flask",
  "flask-sqlalchemy",
  "flask-migrate"
]
```

#### `uv.lock`

Automatically generated by `uv`.

Contains:

- Exact versions
- Dependency tree
- Fully reproducible environment

This cleanly separates:

| File | Purpose |
|--------|----------|
| `pyproject.toml` | What we want |
| `uv.lock` | What was installed |

**Benefit:** Easier dependency management while maintaining reproducible builds.

---

## 3. Replaces Multiple Python Tools

`uv` consolidates functionality traditionally handled by multiple tools.

### Virtual Environment Management

Instead of:

```bash
python3 -m venv .venv
```

Use:

```bash
uv venv
```

---

### Python Version Management

Instead of:

```bash
pyenv install 3.12
```

Use:

```bash
uv python install 3.12
```

---

### Running Commands

Instead of:

```bash
source .venv/bin/activate
python run.py
```

Use:

```bash
uv run python run.py
```

`uv` automatically discovers and uses the project's virtual environment.

**Benefit:** Simpler developer workflow with fewer tools to maintain.

---

## 4. Better Dependency Resolution

`uv` uses the **PubGrub dependency resolver algorithm**.

Advantages:

- Resolves dependency conflicts extremely quickly.
- Provides clear and readable error messages.
- Makes troubleshooting dependency issues easier.

### Example

Instead of cryptic dependency errors, `uv` clearly identifies:

```text
Package A requires Flask <3.0
Package B requires Flask >=3.0
```

**Benefit:** Faster debugging and dependency conflict resolution.

---

## 5. Optimized Docker Builds

In Docker multi-stage builds, dependency installation is often one of the slowest steps.

### Traditional Approach

```dockerfile
COPY requirements.txt .
RUN pip install -r requirements.txt
```

### UV Approach

```dockerfile
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen
```

### Why This Is Better

- Faster dependency installation.
- Deterministic builds.
- Better layer caching.
- No dependency drift.

Because `uv.lock` is committed to Git:

```bash
uv sync --frozen
```

guarantees that:

- Local development
- CI pipelines
- Docker images
- Production environments

all use the exact same dependency versions.

**Benefit:** Eliminates "works on my machine" dependency issues.
